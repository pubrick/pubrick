# Pubrick v0.1.0-beta.1 — proposed prerelease

**Status: offline draft; not published.** The version tag, GHCR images and release
assets have not been created. Source revision: pending the final reviewed,

feature-branch revision or invent image digests.

## What you can do

- Organize workspaces, brands and channels; collect stories and reviewed topics;
  generate, edit and review drafts, with history and calendar planning. Autopilot
  prepares drafts; publication still requires human approval.
- Bring your own API credentials for Google, OpenRouter, OpenAI, Anthropic,
  DeepSeek, Vertex AI or a supported public OpenAI-compatible endpoint. Provider
  and model selection is explicit; usage with unknown cost stays unknown.
  Images, knowledge embeddings and several enrichment features retain their
  separate Google credential requirement. See [provider setup](../llm-providers.md).
- Deliver through supported Telegram, VK, MAX, Bluesky and Mastodon adapters.
  Other listed destinations use explicit manual publication workflows. A manual
  handoff is not a native integration; credentials and platform permissions remain
  required. See the [capability inventory](../porting-status.md).
- Run the same open-source product on your own server. Self-hosted mode does not
  require SMTP or billing configuration. Owners and admins can export workspace
  data; operators have consistent backup/restore tooling and a bounded, read-only
  [installation status command](../hosted-operations.md).

## Installation and upgrade

Follow [self-hosting](../self-hosting.md) for the current source installation.
Set the actual browser `PUBLIC_ORIGIN`, a database password and independently
generated authentication and credential-encryption secrets in `.env`.

The planned release workflow builds API, worker and web images for AMD64 and
ARM64 from one reviewed source revision. Once published and verified, use the
three digests from that release's `release-images.env` and `release-manifest.json`.
Use both Compose files in order for every image-based operation; the release
overlay requires Docker Compose 2.24.4 or newer. See the [release procedure](../releases.md).
Published-image installation and both-architecture verification are still pending.

**Before upgrading, back up PostgreSQL, media, `.env` and the complete encryption
key ring together.** Stop the old worker before starting the upgraded API, which
applies database migrations at startup. Update all three images and Compose files
from the same release. Keep the existing project name and PostgreSQL 16-compatible
data volume. An older image alone is not a rollback: test restoration of the
matching database/media/key snapshot into an empty, disposable target first.
[Recovery](../backup-restore.md) leaves workers stopped until explicitly resumed.

## Beta limits

Hosted mode is a BYOK development capability with verified email, durable mail,
invitations, sandbox subscription state and server-side resource/concurrency
admission. Offline fixtures demonstrate local behavior, not payment settlement.
Trials are disabled. Real payment sandbox acceptance, commercial plans and public
deployment operations remain unresolved; this proposal does not announce a paid
SaaS service. See the [hosted beta plan](../plans/hosted-beta.md).

Provider and external publication access depend on the operator's credentials.
Local transport/browser verification does not prove every external account or
platform works. Digest traceability does not promise byte-identical rebuilds.
Logical storage accounting includes retained cleanup proofs; it is not a hard
physical disk cap. For setup questions and security reports, use the repository's
[contribution guide](../../CONTRIBUTING.md) and [security policy](../../SECURITY.md).
