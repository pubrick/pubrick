# Manual Autopilot check

An organization owner or admin with manager access to a brand can request a manual check from the brand's Autopilot page. The action asks the existing scheduled Autopilot admission service to evaluate that brand now. It never bypasses the enabled setting, start hour, quiet hours, daily draft limit, recorded spend threshold, unpriced usage hold, organization capacity, selected channels, or approved undated topic requirement. A successful decision creates exactly one queued generation run through the same transaction as its dispatch and pg-boss job. The resulting draft remains subject to human review before publication.

`POST /api/brands/:brandId/autopilot/trigger` returns HTTP 202 with an attempt ID and `queued` status. Concurrent requests for the same active attempt return that attempt; after it closes, a new request is refused for 60 seconds from the previous request. The API locks the brand row and commits the attempt and `autopilot-manual` job together. `GET /api/brands/:brandId/autopilot/attempts` returns the 20 newest scoped attempts, with a closed decision and optional run ID. Both endpoints require an active organization, brand manager access, and organization owner or admin status.

The worker records every admission refusal without a provider call. Its terminal attempt update shares the existing Autopilot dispatch transaction, so a `dispatched` decision cannot appear without a run and generation job. A failed queue insert rolls that transaction back. Manual jobs have no automatic retry because a retry could start an unexpected second draft. A dead-letter consumer and a ten-minute sweep close abandoned attempts as `worker_failed`; the POST path also reconciles stale active attempts under the brand lock. A repeated delivery of a completed attempt does nothing.

The UI labels this as a check, not a promise to generate. Confirmation explains that an eligible topic may incur the organization's provider charges and that publication is still manual. The button is secondary, disabled while saved settings differ from the form, while an attempt is active, and during the cooldown. The history shows the exact decision instead of inventing a predicted scheduler result.
